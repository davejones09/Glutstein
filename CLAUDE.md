# Arbeitsweise für Glutstein

- Erst besprechen, dann bauen. Gebaut, committet und ein PR erstellt wird erst, wenn David „Updaten“ schreibt.
- Jede Änderung auf einem eigenen Branch, dann Pull Request gegen `main`. Nie direkt auf `main` pushen.
- Nach Änderungen: `python3 build.py`, Syntax prüfen, im Browser im Querformat (844×390) testen. Bei Balance-Änderungen die Simulationen in `tools/` laufen lassen.
- `index.html` nur über `build.py` erzeugen.
- Sprache in Spiel, Commits und PRs: Deutsch, locker, ohne Fachjargon.
- Kein Pay-to-win: Glutsteine nur für Aussehen. Rivalen sind Computer und werden nicht als echte Spieler ausgegeben.
